# FlowOrder V6.1.3.1 热修复部署指南

## 修复范围

1. 供应商完工承诺即使被存成当天 00:00 的 ISO 时间，也按业务日期判断，当天不算逾期。
2. 同一订单、同一异常类型的未处理候选在重复巡检时复用，不再每次新增。
3. 新一次规则巡检未再次识别的旧候选自动标记为 `SUPERSEDED`，不再计入角标和当前候选。
4. 历史候选列表隐藏已被替代的记录。

## 部署步骤

1. 在 GitHub 建立 `backup-before-v6.1.3.1` 分支。
2. 将热修复包中的 `agent_api.py`、`main.py`、`v61_extensions.py`、`static/index.html` 和测试文件按目录覆盖。
3. 提交并等待 Railway 自动部署。
4. 检查 `/health`、`/api/agent/status`、`/api/v61/status` 的版本均为 `6.1.3.1`。
5. 强制刷新网页。
6. 再运行一次“仅运行规则巡检”。这次运行会自动清理本次范围内的旧重复候选和旧误报。

## 验收

- 当天供应商承诺不显示“已过期”。
- 同一订单在“最近一次风险订单”中只出现一次。
- 连续运行两次规则巡检，左侧异常候选角标不再持续增加。
- 旧的同日误报和重复候选不再出现在当前候选列表。
- 真实风险不足 7 笔时不补齐，信息缺口仍单独展示。
