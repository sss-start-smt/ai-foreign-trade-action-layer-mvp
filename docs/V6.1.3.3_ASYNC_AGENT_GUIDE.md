# FlowOrder V6.1.3.3 Agent异步运行热修复指南

## 一、为什么需要此版本

V6.1.3.2 使用一个同步 HTTP 请求等待 Coze 完成完整工具链。跨订单诊断期间可能长时间没有返回文本，浏览器或网关会先结束请求，但 Coze 工具和数据库运行仍可能继续并最终完成。用户看到超时后再次点击，会增加重复运行风险。

V6.1.3.3 将“提交目标”和“等待结果”拆开：网站快速得到 `job_id`，后台继续运行，页面定期查询状态。

## 三、部署步骤

1. 在 GitHub 创建 `backup-before-v6.1.3.3`。
2. 按目录覆盖增量包文件并提交：
   `fix: release FlowOrder v6.1.3.3 async agent jobs`
3. 等待 Railway 自动部署。
4. 检查：
   - `/health` 版本为 `6.1.3.3`；
   - `/api/agent/status` 中 `async_agent_chat.available=true`；
   - `/api/v61/status` 版本为 `6.1.3.3`。
5. 浏览器执行 `Ctrl+F5`。
6. 不需要修改或重新发布 Coze Agent，不需要更换插件。

## 四、验收步骤

### 1. 提交任务

输入：

```text
检查我未来14天内最需要处理的订单。
```

点击“启动Agent诊断”。页面应在较短时间内显示：

```text
Agent任务已进入后台队列
job_id: AJOB-...
```

而不是一直锁住请求。

### 2. 运行中状态

页面应持续显示已等待秒数和后台状态。此时可以切换到其他页面，再返回异常诊断页，系统继续查询原任务。

### 3. 完成状态

完成后显示 Coze 文本结果、后台耗时、`run_id` 和当前身份。刷新页面后可查看执行轨迹和诊断结果。

### 4. 防重复

在任务仍处于 `QUEUED` 或 `RUNNING` 时重复提交同一目标，应返回原 `job_id`，不得创建第二个后台任务。

### 5. 失败状态

Coze 失败时显示真实错误，不自动切换为规则巡检。用户需要兜底时仍需明确点击“仅运行规则巡检”。

## 五、接口手工验证

创建任务：

```http
POST /api/agent/chat/jobs
Content-Type: application/json

{
  "question": "检查我未来14天内最需要处理的订单。",
  "current_user_id": "USER-1",
  "current_role": "operator",
  "due_within_days": 14,
  "top_n": 7,
  "create_task_draft": true,
  "create_approval_request": true
}
```

返回应包含：

```json
{
  "job_id": "AJOB-...",
  "status": "QUEUED"
}
```

查询：

```http
GET /api/agent/chat/jobs/AJOB-...
```

状态依次为 `QUEUED`、`RUNNING`、`COMPLETED`，或明确返回 `FAILED`。

## 六、数据库迁移

应用启动时自动执行 `schema.sql`，新增 `agent_chat_jobs`，不删除或修改旧业务数据，无需手工运行 SQL，也不要清空 `/data/action_layer.db`。

## 七、回滚

回滚到 `backup-before-v6.1.3.3` 或 Railway 旧 Deployment。新增表留在数据库中不会影响旧版本，无需删除持久卷。
