# FlowOrder V6.1.3.4 Agent性能优化部署与验收指南

## 1. 本次为什么优化

V6.1.3.3解决了浏览器请求超时，但没有减少Agent本身的执行时间。标准巡检原链路通常包含5次Coze工具往返：

```text
start_agent_run
→ diagnose_priority_orders
→ create_task_draft
→ create_approval_request
→ complete_agent_run
```

后端组合诊断本身通常很快，主要等待发生在模型每次读取工具结果、重新决策并发起下一次工具调用的过程。V6.1.3.4把纯运行管理交给网站后端，并把任务草稿与其关联审批合并为一次专业技能调用。

## 2. 最终结构

```text
用户目标
→ Coze Agent判断这是标准巡检
→ diagnose_priority_orders
→ Agent根据结果决定是否调用create_task_draft
→ create_task_draft同时返回可选approval_id
→ FastAPI自动完成运行记录
→ 网站展示结构化结果与精简摘要
```

Agent仍然负责：目标理解、工具选择、是否创建行动、停止条件和结果组织。

FastAPI新增负责：网站运行ID的创建与结束，以及任务草稿和CREATE_TASK审批的原子关联。

## 6. Coze操作

### 必须操作：更新系统提示词

将补丁中的：

```text
coze/AGENT_SYSTEM_PROMPT_V6_1.md
```

全文替换Coze Agent当前“人设与回复逻辑”，保存并重新发布同一个Bot。

新版提示词会识别：

```text
run_managed_by_backend=true
run_id=AGR-...
response_mode=COMPACT
```

标准网站巡检不得再调用`start_agent_run`和`complete_agent_run`。

### 插件操作：通常不需要重建

后端会读取网站任务中的“需要正式动作时创建审批”选项，因此即使当前插件没有`create_approval_request`新字段，也可在`create_task_draft`调用中自动创建关联审批。

只有希望在Coze调试台手工控制该字段时，才用新版12工具OpenAPI更新插件。原插件路径和Bot ID不变。

### 推荐的Coze模型配置

在不降低工具调用能力的前提下：

- 关闭深度思考或长推理模式；
- 使用当前空间中延迟较低、支持工具调用的模型；
- 最终回答最大长度控制在约600—800 tokens；
- 不要求模型重复输出完整5—7笔订单明细。

模型设置需要在Coze界面完成，不在代码补丁中写死。

## 7. 第一次回归

使用李梅身份，输入：

```text
检查我未来14天内最需要处理的订单。
```

勾选：

```text
为最高优先级生成任务草稿
需要正式动作时创建审批
```

运行完成后查看可审计轨迹。标准结果应主要包含：

```text
diagnose_priority_orders
create_task_draft
backend_finalize_agent_run
```

其中`backend_finalize_agent_run`是网站后端结束运行记录，不是一次Coze模型工具往返。

轨迹中不应再出现：

```text
start_agent_run
create_approval_request（CREATE_TASK场景）
complete_agent_run
```

若用户要求其他正式动作，例如修改订单或接受延期，Agent仍可以单独调用`create_approval_request`。

## 8. ID验收

最高优先级订单需要行动时，`create_task_draft`工具返回应同时包含：

```text
task_draft_id: TDRAFT-...
approval_id: APR-...
approval_status: PENDING
```

如果页面没有勾选创建审批，则只返回任务草稿，不应创建审批。

## 9. 性能测试方法

不要只测试一次。保持订单和输入不变，连续运行3次，记录：

| 次数 | 后台总耗时 | Agent工具调用数 | 风险订单数 | 是否有task_draft_id | 是否有approval_id |
|---|---:|---:|---:|---|---|
| 1 |  |  |  |  |  |
| 2 |  |  |  |  |  |
| 3 |  |  |  |  |  |

使用中位数与V6.1.3.3的137秒基线比较。

建议验收目标：

- 标准Agent工具调用不超过2次；
- 后台总耗时中位数明显低于137秒；
- 诊断订单、风险口径和证据没有减少；
- 任务草稿和审批ID真实存在；
- 没有重复创建任务草稿或审批；
- 规则巡检结果不受影响。

由于Coze模型和网络延迟不完全可控，不把某个固定秒数作为代码正确性的唯一标准。若两次工具调用后仍持续超过90秒，应优先检查Coze模型是否开启深度思考，而不是继续修改订单诊断后端。

## 10. 如何证明仍然是Agent

V6.1.3.4没有让网站直接代替Agent完成业务目标。Agent仍需要：

- 识别标准巡检、单单解释、超时承诺检查或批量更新；
- 选择组合工具还是原子工具；
- 根据诊断结果决定是否创建任务；
- 信息不足时停止或追问；
- 无风险时停止，不创建行动；
- 其他正式动作进入独立审批。

本次删除的是固定、无业务决策价值的运行登记往返，不是Agent决策能力。
